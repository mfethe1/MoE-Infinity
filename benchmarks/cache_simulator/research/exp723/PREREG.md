## Design
- Streams {qwen30b (1,424,640 accesses), granite (638,208)} x caps {256,1024,4096,262144}.
- Units per (stream,cap): fam2 = costfit (A) vs shared_costfit (B); fam3 = costfit3 (A) vs shared_costfit3 (B);
  null = costfit3 (A) vs costfit3 (A', labelled B) — the A/A null control.
- ROUNDS = 8. Per round, per stream (stream order shuffled, Random(723)), ONE fresh spawned worker loads the full
  stream once and runs every cap (cap order shuffled per round, same RNG) and, per cap, the 3 units in fixed order
  fam2, fam3, null. Each unit = 4 timed replays ordered ABBA on even rounds, BAAB on odd rounds.
- Timed replay: build_policy(name, cap, geometry_kwargs) (untimed) -> gc.collect() (untimed) -> CEN._replay
  (the sealed stage-A replay loop, unmodified) timed by time.thread_time_ns (PRIMARY), process_time_ns and
  perf_counter_ns (both descriptive). Policy hit_rate read after every replay.
- Pair ratio of a unit = (B1+B2)/(A1+A2) on the chosen clock. Cell statistic = median over rounds of the pair ratio
  (q25/q75 by linear interpolation also recorded).
- R3 = MAX over the 8 (stream,cap) cells of the fam3 cell median (same max-over-cells form as exp718's R3);
  R3_q25/R3_q75 = that argmax cell's q25/q75. R2 likewise for fam2 (reported; R3 is the flagship gate).
- Wall budget 5.5 h; a round starts a stream only if elapsed <= budget. Expected ~20-30 min per round
  (exp718 per-access costs), i.e. ~3-4 h for 8 rounds.

## Gates and verdict ladder (first match wins; implemented as ladder() with a 15-case boundary self-test that
## must pass before any measurement)
1. SEALED-FAIL — sealed drift, or ANY timed replay's hit_rate != exp718 PASS-1 hit_rate for that
   (stream,cap,policy) (exact float equality; proves every timed replay executed the sealed decision path).
2. INCOMPLETE-BUDGET — fewer than MIN_ROUNDS = 5 complete rounds (both streams) within the budget.
3. TIME-INVALID — the A/A null control fails: pooled median over the 8 cells of the per-cell median null ratio
   outside [0.97, 1.03], OR any cell's median null ratio outside [0.93, 1.07]. Meaning: under this host's
   contention even identical code does not time identically -> no payoff claim is admissible.
4. PAYOFF-UNRESOLVED — the argmax cell's [q25, q75] straddles a decision threshold (q25 <= t < q75 for
   t in {1.10, 1.35}).
5. PAYOFF-CONFIRMED — R3 <= 1.10.
6. PAYOFF-MARGINAL — R3 <= 1.35.
7. PAYOFF-REJECTED — R3 > 1.35.

## Predictions (stated before the run)
Loaded wall R3 in exp718 was x1.24-x1.57 (median x1.41) and stage A x1.13-x1.67; shared views add one indirection
(record lookup in a shared table + live counter) per metadata touch. Prediction: PAYOFF-MARGINAL or PAYOFF-REJECTED,
with the max cell at the eviction-heavy caps (256/1024) where metadata is touched most; CPU-time ratios expected
modestly below the loaded wall ratios. A CONFIRMED result would contradict both prior loaded measurements.

## Consequences
- CONFIRMED -> shared state is a free 2-3x metadata cut: propose adoption for the N-way CostFit heads.
- MARGINAL -> adopt only where per-key metadata is memory-bound (high-cap, many experts); next = profile the
  shared-table hot path (record lookup) for a cheaper layout.
- REJECTED -> shared views intrinsically too slow as implemented; next = profile + array-of-struct redesign.
- TIME-INVALID -> CPU-time pairing is insufficient on this host; next timing attempt must move to an
  isolated/pinned host (Winnie core-pinned or a dedicated window), not another loadavg gate.
- UNRESOLVED -> more rounds at the argmax cell only (a targeted follow-up), no claim.
