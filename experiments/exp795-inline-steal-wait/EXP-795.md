# EXP-795 — Inline work-stealing wait for grouped dispatch drain

**Status: VOID** (pre-declared Gate 1 correctness rule triggered). Credited as
an honest negative with attribution data. Receipt #111.

## What was tested
exp794 showed ~1.46 ms/call host-side drain even at tuned ratio 0.5 — the
route-worker -> exec_queue_ -> GPUExecFunc -> cv-notify round trip paid on
every layer even when all experts are cache-resident.

Patch (src795 tree, binary eba566fb, build 0 errors):
- `core/utils/threadsafe_queue.h`: +TryPopIf (predicate pop, queue untouched
  when front item fails the predicate).
- `core/parallel/expert_dispatcher.cpp` WaitHiddenStates: active
  work-stealing wait — pops GROUPED exec items and runs GroupedExec inline on
  the caller thread (exec_streams_[0]); env kill-switch MOE_INLINE_WAIT=0
  restores the passive cv wait.

## Verdict
Gate 1 required identical greedy tokens across C/P/A. FAILED:
- C vs P (treatment OFF, binary lineage only): 64/256 tokens differ
  (prompts 1,3,4,6) -> cross-binary FP compile noise; the rule's implicit
  same-binary assumption was wrong.
- P vs A (SAME binary, env-only): 15/256, prompt 6 only; 7/8 prompts
  bit-identical.

VOID per pre-declared rule. Observational (not promoted):
- A vs P same-binary delta +6.79% (patch-attributable) but P-arm variance
  high (6.46 first-prompt warm artifact) -> magnitude unreliable.
- P vs C -5.31%: binary lineage is a first-order confound (src788 tree
  carries exp752 retirement code absent from the editable tree).

## Lessons (BELIEFS/next)
1. Correctness gates for kernel/runtime patches must compare the SAME binary
   with an env toggle — or use hamming thresholds vs a measured cross-binary
   noise floor; never cross-binary bit-equality.
2. Inline steal is promising (7/8 prompts identical, possible ~7% gain):
   exp796 = FP-robust re-test (same-binary A/B, 3 reps, hamming gate with
   noise floor, logit-margin capture at divergence points).
