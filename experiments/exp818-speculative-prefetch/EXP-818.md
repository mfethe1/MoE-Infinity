# EXP-818 — Speculative prefetch is a 63% regression on memoryless routing

**Question.** Does moe-infinity's `speculative_prefetch` cut per-token wall by hiding expert fetch-wait (exp794: fetch-wait ≈ 43.7 pts of cost)?

**Method.** 7 arms, un-instrumented wall + token lists only (the exp817 truth standard: min-estimator, block-until-quiet gates). No source patch — `speculative_prefetch` is a script-level config flag (engine source left pristine, sha `542a27f4` restore-verified). WARM8_8 + 3 reps of (OFF, ON), order alternated per rep to balance drift. Probe 8 prompts × 128 gen. Seal `433d37d9…`.

**Results (extract818; walls = 3 reps sorted).**

| condition | walls ms/tok | min |
|---|---|---|
| prefetch OFF | 79.8 / 82.9 / 83.0 | 79.8 |
| prefetch ON | 130.3 / 145.7 / 149.4 | 130.3 |

| gate | value | verdict |
|---|---|---|
| G1 prefetch win ≥5 | **−50.5 ms/tok (a 63% LOSS)** | **FAIL (direction reversed)** |
| S1 output-preserving | 0.552 vs 0.557 floor − 0.5pp | **PASS** |
| S2 min replicated ≤10% | ON 2nd-min = 1.118×min | **FAIL (marginal)** |

S2 caveat: the ON condition's spread (14.7%) comes from prefetch-thread contention interacting with background load. The verdict is robust regardless: **every ON rep (130.3+) is ≥57% slower than every OFF rep (≤83.0)** — six cross-condition comparisons, all same direction.

**Adjudication — speculative prefetch is fundamentally mismatched to this workload.**
1. Prefetch prediction assumes expert sequences are predictable from history. **exp796 showed OLMoE routing is effectively memoryless** (history features ≈ random-init floor). A predictor on a memoryless process is worse than chance at the margin — the prefetch threads fetch experts that will not be used, while contending with the real fetch path for the ones that will. (Correction: an earlier draft said "≥64% slower every rep"; the exact worst-case cross-rep ratio is 130.3/83.0 = 1.57, i.e. ≥57%.)
2. The result refines the fetch-wait story: fetch-wait (43.7 pts) is real and the largest measured wall owner, but **it cannot be attacked with prediction** on this routing distribution. Viable directions remain: resident capacity (exp791: capacity buys +31 pts of residency), cache/eviction policy (exp815.5: LCNU holds the pairing floor), bandwidth/overlap of the known-fetch path.
3. S1 PASS: prefetch changes only fetch timing, not math (agreement 0.552 ≥ floor − 0.5pp).
4. **Operational rule:** `speculative_prefetch` must stay OFF for this engine+model class; any future prefetch design needs a routing-predictability measurement first (and here that measurement already says: not predictable).

**Lineage.** exp794 (fetch-wait 43.7 pts) + exp796 (memoryless routing) + exp817 (un-instrumented truth standard) → **exp818 (prefetch prediction loses +50.5 ms/tok; attack fetch-wait without prediction)**.
