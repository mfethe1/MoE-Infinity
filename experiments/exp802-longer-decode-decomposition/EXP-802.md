# EXP-802 — Longer-decode decomposition: is attention KV-bound as generation lengthens?

**Date:** 2026-11-13 (UTC) · **Status:** COMPLETE · **Credit:** experiment #60 (receipt #119)
**Seal:** `7b632657e85f134610160e3b049e674505d8b19ad016ad7e31b4f4b919bef06d` (winnie `~/exp802-seal.tgz`, 14,853 B)
**Predecessors:** exp790 (decode attribution at 32 tok), exp798/799/801 (inline steal series)

## Question

exp790's decode-time map was measured at 32 generated tokens. At 128 tokens the KV cache is
4× larger (attention memory traffic) and the expert offload path has 4× more steps to amortize
its one-time costs. Which effect dominates? If per-token attention cost scales with KV length,
attention is memory-bound (KV-memory lever). If it is flat, attention is launch/overhead-bound
(kernel-batching lever).

## Preregistered gates (frozen in extract802.py before the run)

- **P1:** PT_attn(128)/PT_attn(32) ≥ 1.5 → attention KV/memory-bound
- **G1:** PT_moe(128)/PT_moe(32) ≤ 0.90 → MoE offload cost front-loaded (amortizes with length)
- **S1:** unaccounted share ≤ 3% per arm
- **S2:** ≥3 clean cells per condition, else VOID; ≥6 flagged arms → VOID
- PT(x) = decode_self_ms(x)/(max_new−1), per-token cost; shares informational only

- clean cells: 4 (32-tok) / 3 (128-tok); flagged: B4 (post-gate only, l1=13.66 — shared-CI
  storm arrived after B4's compute had already finished rc=0; GPU-side clean throughout)

## Verdicts

- **P1 FAIL (0.948)** — per-token attention cost is flat (slightly down) across 4× KV growth.
  **Attention decode is NOT KV/memory-bound at these sequence lengths.** The next attention
  lever is overhead reduction / kernel-launch batching, not KV-memory optimization.
- **G1 PASS (0.8998 ≤ 0.90, borderline by 0.0002)** — MoE per-token cost falls ~10% at the
  longer decode: expert-offload cost is front-loaded and amortizes with generation length.
  Directionally consistent with the residency-warming picture; treat the exact boundary hit
  as weak-positive, not strong.
- **S1 PASS** (unaccounted −3.5%/−3.1% — negative from conservative overlap accounting)
- **S2 PASS** · no VOID

## Interpretation

At OLMoE-1B-7B scale with these prompt lengths, longer generation makes every token slightly
cheaper: the fixed offload/handoff costs amortize while attention's per-token cost does not
grow measurably. Combined with exp790 (~16% attn_core + ~7% qkvo outside expert handling) and
exp794 (~44% fetch-wait + ~33% handoff inside the MoE path), the decode bottleneck is
overhead/launch structure, not KV memory traffic — the kernel-batching lane is the
preregistered next step on P1 failure.
