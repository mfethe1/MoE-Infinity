## Question

Where do the ~82% non-grouped decode milliseconds actually go?

## Method (3 dead ends, 1 working)

CUPTI is dead in this WSL (torch 2.11.0+cu128): torch.profiler returns 0 CUDA events
even for a bare matmul; nsys 2024.6.2 accepts cudaProfilerApi ranges but emits an
empty "Generated:" and no .nsys-rep. Working method: selective forward hooks on named
modules + CUDA event pairs, self-time = inclusive - children-inclusive, decode bucket
= sum(32-tok run) - sum(1-tok run) in one process (profile790d.py, d84bbaac).

## Result (28.16 s decode wall, 99.0% attributed)

| bucket | ms | % of wall |
|---|---|---|
| moe_glue (sparse block self: archer dispatch + grouped GEMMs + glue) | 19145 | **68.0** |
| norm (all RMSNorms) | 3123 | 11.1 |
| attn_core (attention incl. sdpa) | 2869 | 10.2 |
| qkvo_proj | 1315 | 4.7 |
| layer_glue | 683 | 2.4 |
| router gate | 478 | 1.7 |
| unaccounted | 287 | 1.0 |
| lm_head / rotary / embed | 263 | 0.9 |

Cross-check vs exp786: grouped GEMM kernels ~=18% of decode => **dispatch/prefetch
stall ~=50% of wall** — the largest single lever measured in this program.
Attention + projections combined: 14.9%.

## Decision (pre-declared rule)

TARGET=moe_glue: the sparse-MoE block's non-GEMM time (archer runtime expert fetch
waits, per-layer host dispatch) is the next optimization surface. exp791 candidates:
overlap archer expert prefetch with attention compute of the same layer; batch/-cache
per-layer dispatch; reduce sync points. Caveats: event pairs measure stream wall
(host stalls inside the block count — intended); hook overhead inflated absolute
walls ~15% vs unhoked probes (shares are the signal); the 18% GEMM figure is imported
from exp786, not re-measured here.

## Addendum — grouped-decode arm (same day, seal790b, 3 files)

Identical profiler with `MOE_GROUPED_DECODE=1` (production config): wall 27.61 s,
**moe_glue 68.4%** (vs 68.0% native), norm 10.6%, attn_core 9.6%, qkvo 4.4%,
router 1.7%, unaccounted 2.2%. Dispatch-stall estimate 50.4%. The attribution is
config-robust: the barrier structure (`dispatch_local` -> full drain ->
`wait_dispatch_local` per layer per token in SyncOlmoeMoEBlock) dominates both
the native per-expert path and the grouped-kernel path. Addendum seal manifest
