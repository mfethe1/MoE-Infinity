## Interpretation

The frozen per-config determinism gate did its job: rc=9 with NONDET detail is the
sealed verdict and stands — no post-hoc edits. The complete reading of the evidence:

1. **Speed lever CONFIRMED, first positive decode lever of the program**: +9-12%
   batch-1 decode on consumer sm_120 from a shipped-but-gated code path, at zero
   routing cost, using pro6000-tuned tile tables on a 36 SM / 32 MiB L2 card. A
   consumer-retuned table is a plausible further gain (this is a lower bound).
2. **Cost: bit-reproducibility.** The same kernels break run-to-run bit determinism
   (atomic reduction order). Any use needing reproducible outputs (eval harnesses,
   regression tests, scientific pipelines) must pin the default path or add
   determinism flags; throughput-first serving can take the +9-12% directly.
3. exp785's "config-level dispatch surface exhausted" is refined: one shipped lever
   remained reachable via the documented hw-gate lift, and it works. The remaining
   headroom is native-level: consumer-tuned tile tables (retune `pro6000.cu` for
   36 SM), or making the grouped path bit-deterministic.
