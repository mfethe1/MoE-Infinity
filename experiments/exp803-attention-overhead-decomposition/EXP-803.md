# EXP-803 — Attention decode bucket is 98% orchestration overhead, not math

**Question.** exp802 (receipt #119) measured the in-vivo attention bucket at
PT_attn = 127.80 ms/tok (32 tok) / 121.17 ms/tok (128 tok), flat across 4× KV growth.
Flatness said "overhead-bound", but not how much. This experiment replays the exact
attention decode-step math standalone (same GPU, same shapes) to decompose the bucket
into math vs orchestration and size the kernel-batching lever.

**Method.** Standalone replay of OLMoE-1B-7B attention decode step: 16 layers ×
(qkv GEMV 2048→6144, SDPA over fixed KV cache, o-proj GEMV 2048→2048, residual), bf16,
shapes read from the model config.json at runtime. Cells at KV length s ∈ {64…4096};
variants eager(B1), eager(B8 = 8 prompts in one step), CUDA-graph-captured (B1/B8);
30 warmup + 200 CUDA-event-timed steps per cell, median reported; fresh process per
cell; load gates pre+post each cell; WARM throwaway first. No model load, no binary
swap, GPU1 isolated (CUDA_VISIBLE_DEVICES=1). 16/16 cells rc=0, zero flagged, no VOID.
Runner/extractor/replay frozen before run (shas in running.json entry 109).

**Results (median ms/token, 200 steps/cell).**
- eager B1: s64 1.994, s128 1.976, s256 2.481, s512 2.130, s1024 2.443, s2048 2.505, s4096 3.175
- eager B8: s128 2.183 (0.273/prompt), s1024 5.251 (0.656/prompt), s4096 15.227 (1.903/prompt)
- graph B1: s128 1.756 (1.125× vs eager), s1024 2.055 (1.19×), s4096 3.059 (1.04×)
- graph B8: s128 2.054, s1024 4.999
- WARM (2.004) ≈ E2 (1.976) — warmup discipline held.

**Gates (preregistered).**
- P1 PASS — eager B1 s128 = 1.976 ms = 1.63% of in-vivo 121.17 ms; orchestration share 98.4% (gate ≤20%).
- G1 FAIL — replay s4096/s64 = 1.59 vs gate ≤1.5. Pure math does grow mildly with KV
  (64× more KV bytes to read); absolute cost stays ≤3.2 ms. The in-vivo flatness is
  overhead masking the read cost, not free reads.
- S1 PASS — B8 per-prompt 0.273 ms ≤ 0.15 × B1 (13.8% marginal): batching 8 prompts
  amortizes 7.2× at s128.
- S2 PASS — 10 clean eager cells, 0 flagged, void=false.
- Graph cells (non-gating): capture WORKS on WSL2 (200/200 steps in all 5 cells; the
  `graph_ok:false` flags in cell JSONs are a labeling bug in replay803.py — the flag
  never flips true for the graph variant; medians and step counts are real). Graphs
  trim only 0.12–0.47 ms/step: the eager loop's ~48 launches cost little.

**Interpretation.** The in-vivo attention bucket is ~61× the pure math cost, and
CUDA-graphing the math recovers almost none of the gap — so the overhead is NOT
cudaLaunchKernel API cost. It is host-side orchestration inside the MoE-Infinity
runtime around each layer (Python hooks, per-layer host logic, sync points with the
CPU expert-offload pipeline). The lever is collapsing that per-layer host work:
batched layer execution / fewer sync points / taking attention out of the hooked
offload path — not kernel-launch micro-optimization and not KV-memory layout.
B8 scaling also shows the attention reads themselves bite only at large KV × batch
(15.2 ms at B8 s4096), far above OLMoE's current operating point.

**Routing.** exp804: prototype collapsing per-layer host orchestration around
attention (grouped layer execution or unhooked attention path), measure PT_attn
in-vivo delta. If the gap closes even partially, the same treatment applies to the
qkvo/proj buckets (exp790: attn 10.2% + qkvo 4.7% of decode).
