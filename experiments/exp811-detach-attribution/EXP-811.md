# EXP-811 — Detach-storm attribution: 100% of the 1,191 detaches/token come from the offload engine's per-module hooks

**Question.** exp809: `aten.detach` = 1,191/token = 39.6% of the op stream. Which code sites own them (and the `mul`/`_to_copy` overhead ops)? This names the addressable call path.

**Method.** `TorchDispatchMode` with 1-in-1000 stack sampling of target ops; innermost framework frame (`transformers`/`moe_infinity`/`torch`) recorded as `file:line:func`. Arms WARM_8 then BASE_B_128/BASE_B2_128 (bare-ids generate, exp809 pattern). First-try clean battery, 3/3 rc=0.

**Gates (preregistered).** P1 single detach site ≥0.50 per cell; G1 top-3 ≥0.80; S1 ≥200 detach samples per cell; S2 top-1 site identical across cells + walls in [100, 200] ms/tok (instrumented).

**Findings.**
1. **P1/G1 FAIL is the answer at site granularity — the detach storm is spread almost uniformly across 8 lines of one engine file.** Derived observation from the same frozen data (no gate change): top-8 sites = 1,211/1,214 ≈ **99.8% of detach samples, all inside `moe_infinity`'s `model_offload.py` pre/post forward module hooks**. The model's own math contributes essentially zero detaches.
2. **Every module forward crosses a pre-hook and a post-hook, each issuing multiple detaches** — per token × per module (16 layers × ~7 modules) ≈ the 1,191/token storm. The hooks are engine glue for expert offload bookkeeping, not math.
3. `mul`/`_to_copy` by contrast live in HF modeling code (RMSNorm/rope) — ordinary per-layer math, addressable only by kernel fusion, not by engine cleanup.
4. **Actionable target isolated**: reducing hook detaches (e.g. caching detached views per module, or skipping redundant detach when no offload action is taken) bounds up to ~28 ms/tok of the 72 ms userspace burn (exp809's detach share × 24 µs/op). This is a localized, upstream-able fix in one file.

**Lineage.** exp809 (3,008 ops/tok; detach 39.6%) → exp810 (batching unavailable client-side) → **exp811 (detach storm = 99.8% engine offload hooks, `model_offload.py`)**.
