# EXP-820 — Eviction-policy bake-off at `device_memory_ratio=0.65`

**Status: COMPLETE** (2026-11-14). Registered frozen before run (gates + script shas in `running.json`).

## Question

exp819 found the capacity curve U-shaped with optimum 0.50 and attributed the high-ratio regression to LCNU churn (predicted by exp791). Can a modern eviction policy (arc / lirs / s3fifo / w_tinylfu — the native policy set of `core/prefetch/eviction_policy.cpp`) unlock the 0.65 regime?

## Design (frozen pre-run)

- Ratio fixed 0.65; policies: lcnu (baseline), arc, lirs, s3fifo, w_tinylfu; 3 reps each, rotated arm orders (rep2 reversed, rep3 rotated).
- Min-estimator; un-instrumented truth standard (wall + token lists only, exp817); quiet gates (3600s budget) with clean INFRA-ABORT; throwaway warmup arm.
- S1 output-preserving gate in the exp813 agreement-rate pattern: each policy's agreement vs lcnu must be ≥ the lcnu-vs-lcnu floor − 0.5pp.

## Results (all numbers re-derived by `verify820.py`; cross-check vs extractor `true`)

Min walls (ms/tok): lcnu 82.3 (82.3/88.1/94.1), arc 79.5 (79.5/79.7/84.7), lirs 81.1 (81.1/83.3/128.2), **s3fifo 78.4** (78.4/81.0/88.7), w_tinylfu 84.3 (84.3/88.1/96.2).

- **G1 FAIL** (policy win ≥5 ms/tok): best alt s3fifo beats lcnu by 3.9 ms/tok — s3fifo is **4.7% faster than lcnu** at 0.65 (equivalently, lcnu is **5.0% slower than s3fifo**), below the preregistered bar.
- **G2 TRUE** (best alt ≤ 79.9×1.02): s3fifo 78.4 ≤ 81.5 — matches the exp819 0.50 sweet-spot anchor. **Cross-battery caveat:** the same condition (lcnu @ 0.65) measured 89.9 ms/tok in exp819 vs 82.3 here (−7.6 ms/tok), so cross-battery anchors are noisy; only within-battery comparisons are valid. The G2 anchor is preregistered but must not be read as "s3fifo beats the 0.50 optimum".
- **S1 FAIL** (output-preserving): w_tinylfu agreement vs lcnu 0.5058 < floor 0.5143 − 0.5pp (marginal, 0.35pp); arc 0.5800 / lirs 0.5562 / s3fifo 0.5213 pass. The floor itself is low (0.5143) — greedy decode is heavily nondeterministic cross-process, consistent with exp813.
- **S2 TRUE** (min replicated ≤10%): all five conditions (lirs's 3rd rep 128.2 is an outlier; S2 uses 2nd-min 83.3/81.1 = 1.027).

## Verdict

Policy choice is a **second-order lever** (~4% best case at 0.65) and does **not** rescue the high-cache regime into a ≥5 ms/tok win. The exp819 conclusion stands: baseline at 0.50. s3fifo is the best policy tested and a sensible default for this workload if chasing the last few percent; w_tinylfu is the worst here (slower than lcnu and marginally below the S1 floor). Follow-up candidate: sweep ratio under s3fifo (0.35/0.50/0.65) to test whether the U-shape flattens under a better policy.
