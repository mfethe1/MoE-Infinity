# EXP-804 — The attention-bucket overhead blocks in native code, not Python

**Question.** exp803 (receipt #120) showed the in-vivo attention bucket is 98.4%
orchestration overhead vs pure math, and CUDA graphs recovered none of it. WHERE does
the host block? Localize the gap (~129 ms/tok) to named Python-visible host-blocking
sites: `torch.cuda.synchronize`, `Event.synchronize`, `Tensor.item/.cpu/.tolist/.numpy`,
`Tensor.to` (D2H).

**Method.** Frozen profile802.py harness (identical hooks, envelope: OLMoE-1B-7B bf16,
ratio 0.50, MOE_GROUPED_DECODE=1, threads 4, GPU1, 8 prompts, pre/full phases) plus
monkeypatch wall-timers on those sites, counters per phase, decode share = full−pre per
token. Arms: WARM (patched, 8 tok), CAL (exp803 replay loop with patches active),
BASE_A/B (no patch, 32/128 tok), PA1/PB1 (patched), PA2/PB2 (replicates). Token-id
sha256 hashes per prompt. Python-only; binary `d252620b` untouched. 8/8 cells rc=0,
0 flagged, no VOID. Shas frozen pre-run (running.json entry 110); seal `4b90de5a…6007`.

**Results.**
- **P1 FAIL — decisively.** All Python-visible sites together = **7.94 ms/tok
  (6.2% of the 128.76 ms gap)**: `Tensor.to_d2h` 7.94, `Tensor.item` 0.05,
  `tolist` 0.03, `cpu` 0.02, `cuda.synchronize` ≈ 0.00. The attention bucket does
  NOT block in any Python-visible torch call.
- **G1 FAIL**: top site 6.2% (gate ≥25%).
- **S2 PASS**: patched vs base PT_attn within 3.5% (instrumentation not distorting);
  7 clean decode cells.
- **S1 FAIL — informative sub-finding:** token hashes differ across processes.
  Pairwise: patch-vs-patch PA1/PA2 = 2/8 identical, PB1/PB2 = 3/8 — same as
  patch-vs-base (3-6/8). Greedy decode at this envelope (threaded CPU experts, bf16)
  is **not token-reproducible across processes**, independent of instrumentation.
  Extends exp796 (bit-level token gates dead) to cross-process greedy instability;
  exp782's BOTH-STABLE does not generalize here.
- CAL: patched replay 2.435 vs 1.976 ms/step → ~0.46 ms/step instrumentation ceiling
  at 1 sync/step — an upper bound on wrapper cost; decode site numbers are if anything
  overcounts, strengthening the P1 FAIL.
- PT_attn replication held across 4 more cells (124.4–134.0 ms/tok, mean ~129).

**Interpretation.** Combined stack: attention bucket ≈ 121–129 ms/tok (exp802/804);
pure math 1.98 ms (exp803); graphs recover ~0.2 ms (exp803); Python-visible blocking
≈ 7.9 ms (exp804). Conclusion: **~110 ms/tok — the dominant share — blocks inside the
native C++ offload pipeline** (dbuf chain / expert-dispatch threads / stream waits the
main thread sits in while inside attention forward), consistent with exp794's
fetch-wait 43.7% + handoff 33% attribution living under the attention bracket.

**Routing.** exp805: native attribution — sample `/proc/<pid>/task/*/wchan` (+ kernel
stack) of the decode process at 20–50 Hz during the 128-tok arm; classify main-thread
wait channels (futex → dispatch sync; ioctl/poll → CUDA/driver; schedule → CPU
contention). Target: a single named native mechanism ≥50% of main-thread decode samples
→ the concrete patch site for exp806.

**Envelope.** Winnie WSL GPU1, unit `exp804sites`, 2026-11-13 03:43–03:58 UTC,
in-vivo constants from frozen extract802/803 outputs (receipts #119/#120).
