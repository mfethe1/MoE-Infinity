# exp826 stage 0 — router-trace overlap study (offline, counts-only)

Artifact: exp826-routing-steps.json (16 diverse prompts, 16 layers, greedy 64-token decode,
OLMoE-1B-7B top-8 of 64 experts/layer/step; run 2026-11-19T02:48Z, unit exp826-s0r2).
Analysis: analyze_routing.py (same directory) — every number below is its stdout.

## Findings

1. **Step-aligned expert overlap is ~12.5%** (mean pairwise Jaccard 0.1246 over decode steps
   1+; step 0 = shared chat-template prefill, overlap 0.995). Two prompts running concurrently
   share ~1 of their 8 per-step experts.
2. **A random b8 batch activates ~38 distinct experts per layer per step** (vs 8 for b1) —
   the per-step expert working set grows ~4.7x when batching 8 diverse prompts. This is the
   measured mechanism behind exp825's anti-amortization: more prompts = more dispatch events
   and more cache misses per step, not amortized fixed cost.
3. **Grouping headroom is small**: greedy best-8 pairing on first-8-step windows reaches 0.6206
   mean overlap vs 0.5383 random-pair (best single pair 0.7527). Even perfect pairing cuts
   distinct-experts-per-step by far less than the 25% threshold Mythos review #1 set as the
   kill line for the residency-aware-grouping lane.
4. **No hot-expert set to cache**: top-8 hottest experts carry only 29-32% of use; 63-64 of 64
   experts active per layer across 16 prompts. Usage is near-uniform; LRU/LCU-style residency
   cannot concentrate hits.
5. Whole-generation unions saturate (every prompt touches all 64 experts/layer; Jaccard 1.0) —
   confirming union-level statistics carry zero grouping signal.

## Verdict (stage 0)

**Expert-residency-aware grouping for diverse-prompt serving is DEAD at this granularity**
(routing is diverse and near-uniform across experts at step level). The only surviving overlap
structure is the **shared-prefix step-0 effect** (0.995): batching requests that share a literal
prefix (same system prompt/few-shot) does co-route during the prefix — a serving-layer
observation, not an engine change. exp825's batching result is now mechanistically explained:
batch multiplies per-step dispatch events ~4.7x at b8 while GPU math stays flat.

Counts-only study per the simulation trust rule (walls never predicted from this).
