## Question

Within the shipped runtime override `MOE_GROUPED_MOE_CFG` (the 8 instantiated
(mt,wr,wk,u) launch configs of `grouped_moe_decode_pro6000.cu`), does any
configuration beat the shipped default table for OLMoE-1B-7B batch-1 decode on
consumer sm_120 (RTX 5060 Ti) at ratio 0.25 with the hw-gate lifted
(`MOE_INFINITY_UNVALIDATED_HW=1`, exp786 regime)? Secondary: does WK=1 (no
K-split) reduce the grouped path's run-to-run output nondeterminism?

## Interpretation

1. exp786's +9-12% grouped-decode win needs no consumer retune at the launch-table
   level: the pro6000-tuned defaults are within noise of the best shipped
   alternative on a 36 SM / 32 MiB L2 part. Further speed on this path requires
   NEW kernel instantiations (edit + nvcc rebuild), not table selection.
2. The bit-nondeterminism cost of grouped decode is structural (expert-order
   atomics). A deterministic grouped path needs a kernel change (fixed-order or
   two-pass accumulation), not a launch-config choice. WK=1 ≈ default confirms
   the K-split tree is already deterministic per-expert (smem + syncthreads).
3. Combined with exp786: consumer-GPU users can take +9-12% via
   `MOE_INFINITY_UNVALIDATED_HW=1` with the default table and no tuning knobs.
