# EXP-812 — Hook-detach elimination: 99.7% detach removal recovers 13.5 ms/tok (first mitigation)

**Question.** exp811 localized 1,191 detaches/token to `model_offload.py` pre/post forward hooks (bookkeeping: `named_parameters()` detached views + repeated `param.data` accesses). Does eliminating them reduce the op stream and wall time without changing outputs?

**Method.** A/B on the editable engine source (pristine sha `542a27f478c99661…`): BASE arms (WARM + 2× B128) run and sealed first; then a 4-line-loop-header + 8-replacement patch (`named_parameters()`/`parameters()` → `_parameters`/`_buffers` dict values with `None` filter; `param.data.data_ptr()` → `param.data_ptr()`; `.data.device` → `.device`; the semantic `param.data = param.data.to(...)` moves untouched); PATCH arms (WARM + 2× B128); source RESTORE-VERIFIED vs pristine sha. CounterMode op census + walls + greedy token digests per arm. Three attempts: two mechanical Voids (loop-tuple unpack; `_parameters` `None` entries for bias-less Linear), both caught by a patch-smoke gate + restore trap before any mitigation data; final attempt-3 first-try clean battery.

**Gates (preregistered).** P1 patched detach/tok ≤ 50% of BASE; G1 wall ≤ BASE − 10 ms/tok; S1 greedy token digests identical across all 4 arms; S2 BASE detach replication within 1%.

**Results (frozen mit-*.json, extract812.json; seal sha256 begins 6e0fd2db).**

| metric | BASE_B / BASE_B2 | PATCH_B / PATCH_B2 | gate |
|---|---|---|---|
| detach/tok | 1191.3 / 1191.3 | **4.0 / 4.0** | **P1 PASS** (−99.7%) |
| total ops/tok | 3010.9 / 3010.9 | 1823.6 / 1823.6 | (−39.4%) |
| wall ms/tok | 128.4 / 126.2 | **114.6 / 112.9** | **G1 PASS** (−13.8 / −13.3) |
| digest equality | — | — | **S1 FAIL-as-written** (see adjudication) |
| BASE replication | exact | — | **S2 PASS** |

**S1 adjudication (preregistered rule applied honestly).** Digests differ across all four arms — **including BASE_B vs BASE_B2 on identical code**. The gate's implicit premise (cross-run greedy token stability) is refuted by the experiment's own baseline cells: known cross-process nondeterminism (exp796 bit-level; exp804 cross-process). Evidence the outputs nonetheless match where determinism holds: all 6 arm pairs agree **16/16 tokens on both sampled sequences** (first and last prompt); divergence is late-sequence, indistinguishable between BASE-vs-BASE and BASE-vs-PATCH. Verdict: **S1 indeterminate-by-refuted-premise** (pre-declared dead gate class carried from the determinism work — a logits/agreement gate should have been preregistered). No evidence of semantic breakage; a stronger S1 (per-prompt agreement rate) is the follow-up.

**Findings.**
1. **Real wall recovery: −13.5 ms/tok (10.6% of 127.4)** from removing bookkeeping detaches alone. The exp809 bound (~28 ms/tok) is measured at 13.5 — the rest of the burn is the other 1,823 ops/tok (views/copies/allocs/RMSNorm/rope), the next fusion/dispatch targets.
2. Detach residual = 4.0/tok (was 1191.3) — the storm is gone; replication exact in both cells.
3. The patch is **upstream-able**: one Python file, behavior-preserving under the sampled-output check, no engine/binary changes. Candidate for a real PR to EfficientMoE/MoE-Infinity (owner decision on timing).
4. Patch-smoke gate + restore trap (added after attempt-1) proved its worth: both mechanical failures aborted before burning PATCH cells and left the tree pristine (sha-verified).

**Lineage.** exp809 (3,008 ops/tok; detach 39.6%) → exp810 (batching unavailable client-side) → exp811 (storm = engine hooks) → **exp812 (hook-detach elimination: −13.5 ms/tok, 99.7% detach removal, sampled outputs intact)**.
